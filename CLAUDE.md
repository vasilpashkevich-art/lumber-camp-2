**Это вторая ветка игры** (копия основной версии 52 от 08.10.2026), развивается в свою сторону. Основная игра — отдельно: артефакт https://claude.ai/artifact/Hpt9gL3yZRckNAYWFgi1Fu, репозиторий lumber-camp; её здесь не трогать. Ключи сохранений во второй ветке свои (`lumber-camp2-*`), чтобы на сайте сохранения двух версий не затирали друг друга.

**Направление ветки II — открытый мир в духе WoW (зоны по уровням, задания, возрождение мобов, золото, профессии, подземелья, уровни до 50). Всё решённое — в `CONCEPT.md`, читать перед любой работой.** С v53 игра написана заново модулями; код ветки I (v52) лежит в `legacy/v52/` — брать оттуда рисовку и механики, когда они нужны (CONCEPT.md §10).

- Главная версия ветки — артефакт в Claude: https://claude.ai/artifact/7CSM76BvXpvGd4ZvaXuyWM (каждая новая версия публикуется поверх, ссылка не меняется).

- Сохранения только в браузере (localStorage). Онлайн-сохранения и логин не делать, пока Василий сам не попросит.
- **Только компьютер (большой экран).** Под телефон ничего не делаем и не проверяем: ни раскладку, ни касания, ни снимки (решение Василия 08.10.2026). Старый код для касаний не трогаем, но и не развиваем.

## Как работаем с запросом
1. **Выслушать всё.** Пересказать списком, что понято, и спросить: «Это всё на сейчас или добавишь ещё?» Код не трогать до подтверждения.
2. **Критично оценить.** Если идея ломает баланс, противоречит прошлым решениям или есть способ лучше — сказать прямо, дать 2–3 варианта, для каждого средний и худший сценарий (не лучший).
3. **Уточнять только то, что меняет результат.** Мелочи решать самому и называть, что решено.
4. **Одна версия на весь пакет.** Всё подтверждённое делается за один заход, без серии мелких правок.
5. **Исключения:** вопрос «как это работает» — ответ сразу, без кода. Жалоба на ошибку — сразу найти и показать причину; исправлять после «да», если Василий не сказал «исправь» сам.

## Устройство кода
```
data/        — числа и содержимое: balance.js (опыт, мобы по уровню, добыча, таймеры), classes.js, mobs.js, zones.js
src/main.js  — запуск: экран выбора героя → мир, связывает всё ниже
src/engine/  — render.js (рисование), input.js, audio.js (+ aud51.js из ветки I), save.js (слоты, файл), util.js
src/world/   — world.js: граница зоны, деревья, лагеря, стена и ворота столицы, столкновения
src/entities/— hero.js: новый герой, характеристики, опыт
src/systems/ — game.js (ход игры: бой, мобы, добыча, смерть, торговля), items.js (вещи, облик по ярусам)
src/ui/      — select.js (экран входа), hud.js, windows.js (персонаж, рынок, меню, гибель), icons.js, dom.js
src/art/     — hero.js (облик по вещам), rig.js (анимированные люди, собирается из tools/parts/rig.tpl.js), beasts.js (звери, 3 вида), sprites.js (готовые картинки), look.js/bld.js/undead.js — рисовка из ветки I без изменений
src/page.html— разметка и стили, сюда вставляется собранный скрипт
tools/       — build.mjs (сборка), sim.mjs (автоигрок), proto/ (эскизы)
tests/       — *.test.mjs (механики, сохранения, автоигрок), browser/smoke.cjs (снимки в браузере)
```

## Как делать изменения
- Новое содержимое (зона, моб, вещь, задание) — **записью в `data/`**, а не новым кодом. Код в `src/systems/` работает с любыми данными одинаково.
- `src/systems/` и `src/world/` — без рисования и без DOM: их гоняют тесты и автоигрок в node. Всё, что игрок должен увидеть или услышать, — событием в `G.ev` или эффектом в `G.fx`.
- Сложное рисование — один раз в готовую картинку (`sprite()` в `src/art/sprites.js`).
- Сохранение героя: `newHero()` + `migrate()` в `src/engine/save.js`. Любое новое поле — с значением по умолчанию в `migrate()`; при несовместимых изменениях поднимать `HERO_V`. Прогресс игрока не должен теряться никогда.
- Ключи `localStorage` — только `lumber-camp2-*`.
- Мир строится из данных зоны и её `seed`; новые объекты генерировать отдельно, чтобы старые не сдвигались.
- Тексты в игре по-русски, с правильным родом и падежами; без технических слов.
- Сборка: `npm install` (один раз), `npm run build` → `dist/lumber-camp.html` (артефакт) и `index.html` (сайт).

## Проверка перед выдачей
- `npm test` — механики, сохранения и автоигрок (3 класса по 40 минут игры) без ошибок.
- Баланс — `node tools/sim.mjs all 90`: минуты до каждого уровня, смерти, золото. Это идеальный игрок: живой игрок медленнее в 1,5–2 раза.
- Новые механики — новый тест в `tests/*.test.mjs`.
- Всё, что видно глазами, — `NODE_PATH=$(npm root -g) node tests/browser/smoke.cjs` (снимки в `tests/browser/out/`, только экраны компьютера), посмотреть снимки самому. В адресе `#dev` — доступ к игре для снимков (`window.__G`).
- Проверить загрузку старого сохранения.

## Выдача
1. `npm run build`, `cp dist/lumber-camp.html snapshots/lumber-camp-vNN.html`.
2. Опубликовать `dist/lumber-camp.html` артефактом поверх той же ссылки (Artifact publish, `url` выше).
3. Коммит «Версия NN: …» от имени Vasil <vasil.pashkevich@gmail.com> и `git push origin main`.
4. Короткий отчёт: что изменилось, что проверено, средний и худший сценарий.
